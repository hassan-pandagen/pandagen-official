# Page and buyer-journey audit

Reviewed 14 September 2026. This is a source-based audit of PandaCodeGen's existing pages, prepared alongside the work-index redesign and external agency research. The `/work` observations describe the page at the start of that redesign, not its final implementation. Other observations describe the source inspected during this session. Line references can move as implementation continues.

The main design problem is the allocation of attention: the site sells custom work, but much of the available space explains assessment, evidence and contract procedures. Work examples should let a buyer see the delivered website or application, understand the problem solved, and identify the team's role. A concise qualification belongs beside a result; it does not need to become the main subject of every commercial page.

This report makes no claim to have rendered every route. Layout observations follow component order, responsive classes and content. Browser appearance, responsive overflow, contrast, loading behavior, booking and form delivery require the separate runtime checks described below. No application code was edited by this audit.

## Coverage

The repository contains **136 `page.tsx` files**: 89 within `/blog` and 47 elsewhere. The blog total includes the index and dynamic topic template, leaving 87 individual article routes. A dynamic topic template is not a count of all generated topic URLs. The 47 other files include ten French/German wrappers, the WordPress redirect and an internal demo.

## Shared design decisions

Keep the existing warm paper/charcoal/cognac identity, real founder images and real project imagery. Change hierarchy and composition before introducing a new visual brand. Service pages currently repeat huge centered headings, pill labels, icon cards, comparison blocks and dark closing panels. Assign a small number of patterns to actual tasks: portfolio preview, deliverable list, comparison table, short process, price summary and FAQ. Avoid another unique decorative widget for each route.

Navigation already exposes services, work, pricing, partners and company pages. The service menu can group **migrations**, **commerce** and **applications/integrations** so eight platform labels are easier to scan. Work should open a useful gallery directly. The footer currently starts with another large migration CTA on every English page and then presents many links; use a compact footer on contact, policy and reference routes so the user's completed task does not immediately restart the sales pitch. [Header:31](../../../src/components/layout/Header.tsx#L31), [Footer:31](../../../src/components/layout/Footer.tsx#L31).

Use one reviewable case-study summary model across the work index, homepage and services: name; approved preview; client relationship; project type; concrete delivered scope; case-study/live link; optional sourced result. This prevents the current disagreement between the six written case studies, NorthDeck's live-only entry and the service component's separate four-project roster. Disclose affiliations without placing every entry inside a long policy statement.
