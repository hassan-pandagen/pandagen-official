## What a check covers

The intended standard is comparison with primary sources, not merely checking that links open.
The follow-up review screened all 92 posts and checked material disputed claims against sources.
It did not independently verify all 464 external URLs. Some Meta pages required login and the full
Mullenweg report was inaccessible; the unverified Mullenweg quotation blocks were removed.
Owner-approved case-study records establish approval, not independent access to raw measurements.

- **Numbers and dates:** prices, plan limits, versions, scores, counts, deadlines. Anything written
  as upcoming that has since happened is rewritten in the past tense.
- **Claims about named companies:** must be sourced. Anything adverse without a source comes out.
- **Links:** a resolving link alone is insufficient; source access limitations remain explicit.
- **Stamps and metadata:** "Reviewed" and "Checked" dates, `modifiedTime`, `dateModified` and
  blog.ts `lastModified` move to the check date when content changes (scripts/check_dates.py keeps
  them equal). Read times are made to agree.
- **First-hand claims** (our own measurements, client results) are kept, and flagged if nothing in
  the repo backs them.

## Rules for fixing

- Fix what's wrong or stale. Don't add claims the post didn't make, and don't rewrite for style.
- Vendor numbers that appear in several places belong in `src/data/spec-facts.json`, with the
  source URL and `verifiedAt`.
- Leave a dated code comment where a fix reverses something a reader might expect to find.
- No em dashes (house style, `scripts/unicode_guard.py`).
- Run `python scripts/check_dates.py`, `python scripts/spec_freshness.py`,
  `node scripts/check-public-claims.mjs` and `npx tsc --noEmit` after each batch.
