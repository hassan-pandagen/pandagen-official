# Desktop and mobile evidence

The observed layout problems concern emphasis, navigation and the distance between related information. The sampled pages rendered successfully; this is not a report of a broken responsive grid. Large headings, long introductory paragraphs, nested summary cards and repeated agreement sections create much of the scrolling burden.

## Coverage

All nine English service pages, the blog index and six articles were rendered at **1440 × 1000** and **390 × 844** using the existing local production build. All 32 captures returned 200 with no detected page errors, horizontal document overflow, failed images or missing targets for the in-page links that existed. These checks do not measure rankings, conversion, field performance or full accessibility conformance. A lack of broken anchor targets is different from having useful contents navigation.

The article sample was: `how-to-migrate-wordpress-to-nextjs`, `website-redesign-cost`, `wordpress-vs-nextjs`, `agentic-browsing-pagespeed-score`, `what-is-llms-txt` and `ai-referral-revenue-2026`. Screenshot inspection covered service openings, all six article openings, selected body/summary sections and the blog index. Full-page captures exist for navigation through the rest of each sampled page; a full-page image is not a claim that every pixel received individual review.

Coordinates below are CSS pixels from document top after loading the content. Document heights include navigation and footer. Font loading, viewport, consent state and later content changes can change coordinates. Measurements describe this snapshot; none is an ideal page-length or answer-position target. The important difference between a GHL integration, a CMS migration and a custom storefront should be apparent before the pricing qualification.

Ordinary explanation should usually remain ordinary prose; comparison data belongs in a usable table; an actual UI or diagnostic output deserves an informative figure caption.

### Blog discovery

The [desktop index capture](screenshots/own-blog-desktop-top.png) shows a large hero, eleven topic-hub links, search and a second collection of filter chips before the first article is visible in useful detail. On mobile the first featured title appears around 1,484px down and the all-guides heading around 2,521px. The complete mobile document is 37,521px tall with the current listing.

These measurements do not require deleting the archive. Give search and one primary topic navigation clear priority; make the distinction between navigating to a topic and filtering the current list explicit if both remain. Bring selected reading closer to those controls and consider a manageable initial article set with accessible continuation. Preserve crawlable article links and useful hub routes when changing the interface.
