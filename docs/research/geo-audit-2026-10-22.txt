PANDACODEGEN GEO AUDIT AND BLIND SOL QUERY BASELINE
22 October 2026

Scope: 92 articles, 11 topic hubs, blog index, 14 English service detail pages, English service index, French and German service indexes: 121 production URLs.
All 121 production URLs returned HTTP 200. Tool scores ranged from 72 to 87 out of 100.
Scores are heuristic checks, not Google rankings, penalties or citation probabilities.
No canonical/index/snippet eligibility blocker was reported. All 92 articles passed the scored Google-readiness checks. This does not prove actual indexing.

- Did not mass-rewrite articles, change publication dates, or alter commercial promises.

RECOMMENDATIONS REVIEWED AND NOT AUTOMATICALLY APPLIED
- Hidden text: sampled detection evidence is closed navigation and its descendants, legitimate toggled UI.
- Four critical instruction flags match ordinary prose: semantic triples, contact creation, and business impact scenarios. No instruction payload was identified in those samples.
- Thirteen service UGC warnings have no LLM instruction samples; they combine a review region with the generic hidden-menu finding.
- Keyword density warnings count the subjects of articles (WordPress, Sanity, Shopify, etc.). Frequency alone is insufficient evidence of stuffing.
- Blank alt warnings include decorative blog-cover artwork, linked thumbnails and repeated avatars. Informative case-study screenshots already have descriptions. No keyword-filled alt text added.
- Date warnings apply to service/index/topic pages, not the 92 articles. No artificial article dates added.
- FAQ, citations, author and form-label suggestions require page context. Existing article sources/FAQ content and real accessible labels should not be replaced by generic boilerplate.
- ai.txt, summary/FAQ/service JSON endpoints, WebMCP and additional Wikipedia/Wikidata profiles are not prerequisites for Google AI eligibility. No invented profiles or unsupported endpoint claims added.
- RSS is a reasonable optional reader feature, not a demonstrated citation blocker. SearchAction should describe a real supported site search, not fabricated behavior.
- The tool mentions a Search Console generative-AI control. This audit did not verify that setting; it is not treated as a finding.

Shared context within each ten-question batch is a limitation. These are Codex Sol web-assisted responses, not consumer ChatGPT UI observations. One run per question, no statistical inference. Local changes were unpublished, so this is a production baseline, not an improvement measurement.
PandaCodeGen appeared in search results for 4/30 queries and in cited answer recommendations for 2/30.
Cited/recommended: medical training website and booking portal; Squarespace migration.
Search results only: Sanity versus Supabase; keeping GoHighLevel CRM while replacing the website.
Question 1 used a search excerpt labeled crawled last week saying ASAM was in testing. The current production service page and local build say live and contain no testing wording. Agent confirmed it did not open the page before answering. Original benchmark answer preserved.

WHAT TO DO NEXT
The valid audit fixes are ready locally. Nothing was committed, pushed or deployed by this audit.
After deployment, request recrawling of the medical service/case study pages if the recent live-status change has not been picked up. Avoid repeatedly rewriting correct copy because an excerpt is old.
Repeat this same query set after indexing has had time to catch up. For an actual ChatGPT consumer benchmark, run the questions in separate temporary chats with search and record citations. Do not compare different methods as a single trend.
Prioritize documented client work and useful independent references. This one run does not justify new near-duplicate landing pages for every query.
