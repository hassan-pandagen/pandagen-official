# Service pages: previous content against the redesign

Reviewed 2 October 2026. This compares the retained earlier `src/app/services/*/PageContent.tsx` pages and `src/data/service-faqs.ts` with the live routes, which now render the shared service design. It records the copy changes made in this pass. It is a content and evidence review, not a prediction of search rankings.

The earlier pages contained useful answers to specific buying questions, but also repeated platform criticism, universal speed or ranking claims, and some migration promises that depended on the client's accounts. The redesigned pages already had a clearer review, proof, choice, scope and FAQ sequence. This pass adds a plain-language scope section to each shared-template page and expands the visible FAQs. The WordPress migration route has its own renderer and was already revised separately.

## Evidence decisions

| Claim or decision | Check | Treatment |
|---|---|---|
| A headless Shopify storefront can use Shopify for products, carts and checkout. | [Shopify Storefront API](https://shopify.dev/docs/storefronts/headless/building-with-the-storefront-api) and [checkout URL guide](https://shopify.dev/docs/storefronts/headless/building-with-the-storefront-api/cart/manage). | Explain that the custom storefront is buyer-facing and Shopify's checkout remains the payment step when Shopify is the chosen backend. |
| A Webflow code export alone reproduces its CMS and other hosted functions. | [Webflow's export exclusions](https://help.webflow.com/hc/en-us/articles/33961386739347-How-do-I-export-my-Webflow-site-code) contradict this. | State that CMS data, forms, search, restricted content and commerce need separate treatment. |
| Wix content and app data will all export in a single portable site. | [Wix's hosting explanation](https://support.wix.com/en/article/exporting-or-embedding-your-wix-site-elsewhere) and [separate Stores product export](https://support.wix.com/en/article/wix-stores-exporting-your-product-list) show different boundaries. | Inventory each content type and app in the client's actual account; quote manual work. |
| Every Squarespace page and feature moves in its XML export. | [Squarespace's export guide](https://support.squarespace.com/hc/en-us/articles/206566687-Exporting-your-site?no_head=1) lists many exclusions, including store pages and more than one blog. | Check the export and identify manual work; no automatic complete-transfer promise. |
| Recurring WooCommerce billing and saved cards always transfer unchanged. | [WooCommerce's subscriber migration guidance](https://woocommerce.com/document/subscriptions/migrating-subscribers-woocommerce-subscriptions/) ties this to the gateway and payment metadata. | Require provider-specific review, renewal testing and a customer-action plan where needed. |
| GHL has integration surfaces for contacts, calendars and event updates. | [HighLevel API reference](https://marketplace.gohighlevel.com/docs/intro/index.html). | Describe an integration as a scoped option and verify access, location, fields and workflows before committing. |
| Redirects guarantee that existing rankings continue. | [Google's site-move guidance](https://developers.google.com/search/docs/crawling-indexing/site-move-with-url-changes). | Map and test URLs, then monitor; no ranking or recovery-date guarantee. |

## Search terms and limits

The retained page titles, categories, descriptions and visible copy cover the primary service and platform terms shown above. An exact phrase in a page is not evidence that it will rank, and extra paragraphs alone are not a search strategy. Search Console data and the WordPress build/migration decision are documented in [the main positioning review](README.md). The current changes focus on answering buyer questions that the old pages covered in greater depth.

The old AI SEO page displays a dated, first-party Generative AI impression figure. I did not repeat it in the shared page because this pass did not independently reconcile that historical export and because impressions are not visits, enquiries or sales. The old pages' universal speed targets, no-downtime language, automatic transfer assertions, vendor cost claims and revenue implications were not copied into the new sections.

## Evidence audit

**Consequential new platform claims checked:** 7 of 7 categories in the table above. **Blocking defects found in these selected additions:** none after narrowing the transfer and outcome wording.

**Not checked:** Every historic claim in the retained `PageContent.tsx` files; each client's actual export permissions, integrations, payments, subscription tokens and contract; the historic AI SEO GSC export; whether the new copy changes rankings or lead quality; final production HTML and indexing. These require project-specific access or a later deployment measurement.

**Evidence boundary:** These pages describe a scoping method and possible implementation routes. They do not assert that every platform feature can move, that every service has a directly matching case study, or that another client's speed, sales or search outcome will recur.
