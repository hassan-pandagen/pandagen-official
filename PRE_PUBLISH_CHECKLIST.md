## Part 2 — Critical Rules (Confirmed This Project)

These are non-negotiable. Breaking them breaks the build or the ranking.

```
❌ NEVER add "use client" to blog page.tsx files
   Reason: Next.js 15 cannot export `metadata` from client components.
   Result: Build fails with "You are attempting to export metadata from a
   component marked with use client".
   Fix: Blog pages are Server Components. Dynamic imports handle client components.

❌ NEVER use <BlogFeatureVisual /> without a category prop
   Reason: BlogFeatureVisual({ category }: { category: string }) requires it.
   Fix: Use specific animation components directly instead:
   - PageSpeedAnimation, SEORankingAnimation, SalesImpactAnimation, etc.

❌ NEVER ping IndexNow with the full URL list repeatedly
   Reason: Bing blacklists domains that ping the same URLs daily.
   Rule: Add only NEW/CHANGED URLs to indexnow-ping.mjs → ping ONCE after deploy → done.

❌ NEVER hardcode FAQs in the schema
   Reason: Creates maintenance hell — two sources of truth.
   Rule: Always pull from blog.ts: blogPosts.find(p => p.id === "slug")?.faqs ?? []
```

## Part 3 — PRE-PUBLISH CHECKLIST

Work through this top-to-bottom before every publish. Every `[ ]` must be ticked.

---

### STEP 0 — Strategic Fit (Do This Before Writing)

```
[ ] Primary keyword has clear commercial or problem-solving intent
    ✓ Good: "why shopify is slow", "wordpress cost 2026", "how to fix core web vitals"
    ✗ Bad:  "what is a website", "web development tips" (no buyer intent)

[ ] Keyword is specific enough to rank in 3–6 months
    ✓ Good: "shopify plus still slow despite paying $2,300"
    ✗ Bad:  "shopify" or "speed" (impossible to rank alone)

[ ] The post targets exactly ONE ICP from this list:
    - Business owner frustrated with slow/expensive WordPress
    - Shopify merchant losing sales to load time
    - E-commerce brand considering headless migration
    - Agency looking for white-label dev partner
    - Developer evaluating Next.js vs WordPress

[ ] CTA matches the reader's specific pain point
    Example: "Fix My WordPress Speed" post → CTA = "Get Free WordPress Speed Audit"
    Never use: "Contact Us" or "Learn More" (zero conversion intent)

[ ] You have a clear hook for the first paragraph — one sentence that makes
    the reader say "yes, that's exactly my problem"
```

---

### STEP 1 — Content Structure (Write in This Exact Order)

```
[ ] H1 title format: [Keyword]: [Emotional/Specific Hook]
    Good: "Shopify Plus Still Slow? Why $2,300/mo Doesn't Fix Core Web Vitals"
    Good: "Why Is My WordPress Site Losing Traffic? The Speed Tax You're Paying"
    Bad:  "Shopify Speed Tips"

[ ] Subtitle (p under H1): One sentence that answers "what will I get from this post?"

[ ] Word count: 2,800+ words minimum
    - 2,800–3,000 = good for most posts
    - 3,000+ = gold standard, especially for competitive keywords
    - 2,200–2,500 = acceptable for niche/B2B posts only
    - Under 2,200 = DO NOT PUBLISH without a specific strategic reason

[ ] Executive Summary box — 4 bullet points, written as reader takeaways
    - Must have: data-speakable="true" on the div
    - Written as: what the reader will know/save/fix after reading
    - Note: NOT every post needs this — story-hook posts can skip it (see UCP post)

[ ] At least 4 H2 subheadings, each containing a keyword
    Format: "Why [Platform] Is [Problem]" / "How to [Fix]" / "What [Result] Looks Like"

[ ] At least 2 data points or statistics per major section
    Numbers = authority. "53% of visitors" beats "many visitors"

[ ] At least 1 real client example or scenario (can be anonymised)
    "A UK e-commerce brand came to us with a 4.2s load time..."

[ ] Post answers the reader's full question — they should not need to Google further

[ ] Mid-article CTA — placed immediately after the "pain" section
    - Wording is specific to this post's problem (NOT copy-pasted from another post)
    - CTA button text = specific action e.g. "Get Free Shopify Audit"
    - Link: https://cal.com/pandagen/discovery

[ ] Bottom CTA — after article content, before FAQ
    - Headline: summarises what the reader gets
    - Description: 1 sentence outcome
    - Button: slightly different wording from mid-article CTA

[ ] FAQ section — minimum 4 questions (5+ preferred)
    - Questions = what people literally type into Google / ask ChatGPT
    - Answers: 2–4 sentences, plain English, no buzzwords
    - Stored in blog.ts faqs[] array (not hardcoded in the JSX)
```

### STEP 2 — E-E-A-T Signals (Google Trust)

```
[ ] BlogAuthor component present — placed after date/meta row

[ ] 6 citations minimum to authoritative external sources
    Best sources: Google, Vercel, Next.js docs, Shopify Developers, Cloudflare,
                  web.dev, Think With Google, Wordfence, industry research
    Never cite:   random blogs, Wikipedia, competitor agencies, Medium

[ ] All citations formatted in Article schema citation[] array:
    { "@type": "CreativeWork", "name": "Source Name", "url": "https://..." }

[ ] If the post is technical: include real numbers and timings
    "Reduces LCP by 1.8 seconds" not "makes it faster"

[ ] If the post covers a platform: link to that platform's official documentation
    WordPress → wordpress.org/support, Shopify → shopify.dev

[ ] First-person voice used — "we built", "our clients", "we've seen"
    This signals real experience, not AI-generated opinion

[ ] datePublished and dateModified set correctly
    On first publish: both = same date
    On update: only change dateModified
```

## Part 4 — The Formula for a Post That Ranks Fast

What `how-to-achieve-100-pagespeed` does that everything else should match:

```
RANKING FORMULA:

1. KEYWORD INTENT
   Use "how to", "why is", "vs", or "cost of" framing.
   These 4 patterns carry the highest commercial intent in B2B search.

2. SCHEMA STACK
   Article + HowTo + FAQPage in the same @graph = eligible for:
   - HowTo rich result (carousel in Google search)
   - FAQ rich result (expandable answers under your listing)
   - AI Overview citation (Google picks structured data)

3. CONTENT STRUCTURE
   Answer → Proof → Steps → FAQ → CTA
   Not: intro → context → body → conclusion (academic style = slow ranking)

4. CITATIONS STRATEGY
   Cite Google's own documentation wherever possible.
   "According to Google's Core Web Vitals documentation..." = authority signal.
   Google's algorithm trusts content that cites Google.

5. WORD COUNT
   Under 2,500 words = can't compete for most keywords.
   3,000 words with real data = outranks 2,000 words with fluff every time.

6. FRESHNESS
   Include "2026" in the title and in the first 100 words.
   Google treats year-tagged content as fresh.
   Update dateModified when you add new sections.

7. CONVERSION (What Traffic Alone Won't Give You)
   Every post must have a CTA that is the exact next step for that specific reader.
   Speed post → "Get Free Speed Audit"
   Cost post → "Get Free WordPress Cost Breakdown"
   Shopify post → "Get Free Shopify Audit"
   Never use: "Contact Us", "Book a Call", "Learn More" (generic = low conversion)
```
